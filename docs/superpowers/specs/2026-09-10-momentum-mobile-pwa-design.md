# Momentum 移动端 PWA 改造设计

日期：2026-09-10

状态：用户已确认

目标：先交付适合个人日常使用的移动端 PWA，再复用同一套移动界面转为 Tauri Android APK。

## 1. 背景与目标

Momentum 已经可以在手机浏览器中打开，也已经配置 `vite-plugin-pwa`、Web App Manifest、Service Worker、安全区变量、Tauri v2 移动端能力和部分响应式样式。当前主要问题不是页面无法加载，而是桌面信息结构被压缩到小屏：内容密度过高、部分点击目标过小、导航和表单仍带有桌面交互特征。

本次改造服务于个人自用，优先级依次为：

1. 手机端不依赖缩放即可阅读和操作。
2. 核心操作适合手指点击，降低误触。
3. 本机数据可靠、可备份、可恢复。
4. 不破坏现有桌面端。
5. 为后续 Tauri Android APK 保留复用路径。

## 2. 已确认的产品决策

- 交付顺序：先 PWA，验证可用性后再构建 APK。
- 部署方式：用户自己的 GitHub Fork 连接 Netlify，使用固定的 `*.netlify.app` 生产地址。
- 第一阶段数据模式：仅保证本机本地数据，不启用 Supabase 登录和云同步。
- 数据迁移：接受 PWA 导出 JSON、APK 导入 JSON 的一次性手动迁移。
- 移动首页：仪表盘结构，包含今日概览和常用链条。
- 任务卡片：信息均衡，“开始”和“预约”两个高频按钮并列显示。
- 一级导航：今天、链条、RSIP、更多。
- 第一阶段业务范围：链条、任务组、预约、专注计时、完成与中断判定、RSIP、本地数据、备份恢复及必要设置。
- 第二阶段优化范围：宠物复杂交互、统计图表小屏重绘、非必要动效和 Tauri 原生能力。

## 3. 现有实现与差距

### 3.1 可直接复用

- `MomentumStorage` 已定义统一存储契约。
- `localStorageAdapter` 和 `SupabaseStorage` 已隔离具体存储实现。
- UI、Domain、Infrastructure、Platform 分层已经建立。
- `MobileBottomNav` 已提供 44px 最小点击区域和安全区处理。
- `editor-responsive.css` 已处理动态视口、键盘高度、滑块触摸和小屏安全区。
- ChainCard 已采用 Container/View 分离，并已有开始、预约和溢出菜单。
- 导入导出服务已覆盖链条、历史、RSIP 和宠物等数据，并有集成测试。
- PWA 已采用 `display: standalone`，具备自动更新和离线静态资源缓存。

### 3.2 第一阶段需要补齐

- 当前 `MobileBottomNav` 仅在 `isTauriMobile` 时渲染，手机浏览器中的 PWA 仍属于 `web`，因此无法获得移动导航。
- 平台能力判断与屏幕布局判断混在一起。运行环境应决定可调用哪些 API，视口与输入方式应决定使用哪种布局。
- 当前移动底栏是“首页、专注、RSIP、设置”；目标导航是“今天、链条、RSIP、更多”，需要为链条区域和更多菜单定义明确行为。
- Dashboard 在小屏仍连续展示 Hero、数据模式提示、签到、推荐和链条区域，首屏信息过多。
- 现有弹窗和复杂表单需要逐个审计，手机端应改成全屏页面或底部抽屉。
- Web 本地模式目前由 localStorage 承载。为提高容量、事务能力和迁移可控性，需要在不丢失旧数据的前提下引入 IndexedDB。

## 4. 总体架构

移动端改造只替换展示与交互，不复制业务规则。

```text
桌面布局 ─┐
          ├─ React UI / Container ─ Domain Hooks / Services ─ MomentumStorage
移动布局 ─┘                                              ├─ IndexedDB（PWA）
                                                        ├─ Supabase（保留但第一阶段不用）
                                                        └─ Tauri/本地实现（APK 后续）
```

平台能力检测继续使用 `platform.ts`，负责区分 `web`、`tauri-desktop` 和 `tauri-mobile`。新增独立的响应式布局判断，例如 `useMobileLayout()`，通过 `matchMedia` 判断窄屏和主要输入方式。任何 PWA 或 Tauri 运行时只要满足小屏条件，都可使用移动布局。

不要通过 User-Agent 单独决定 UI 布局，也不要让 UI 直接导入 IndexedDB 或具体存储适配器。

## 5. 移动端信息架构

### 5.1 底部导航

底部固定四个入口：

1. 今天：今日概览、连续记录、建议任务和高频链条。
2. 链条：全部链条、任务组、暂停项和回收站入口。
3. RSIP：规则树、分组、执行记录和违规处理。
4. 更多：设置、数据导入导出、PWA 状态和次要功能入口。

底栏适用于手机 PWA 和 Tauri Mobile。编辑器、详情页、任务组编辑器和专注模式继续隐藏底栏，改用明确的返回操作。切换一级入口时应保留各自滚动位置；未提交的编辑表单不应因切换入口而静默丢失。

### 5.2 首页

首页采用已确认的仪表盘方案：

- 顶部只保留页面标题、必要状态和轻量入口。
- 今日概览控制在一张卡片内。
- 常用链条以单列卡片展示。
- Daily Check-in、宠物和复杂推荐不阻塞核心任务区域；第一阶段可折叠或移入“更多”。
- 页面底部预留底栏和安全区高度，避免内容被系统导航栏覆盖。

### 5.3 任务卡片

- 卡片信息保持均衡：名称、连续次数、时长、触发动作和必要状态。
- “开始”和“预约”并列，按钮高度至少 44px，优先使用 48px。
- 编辑、删除和其他低频操作保留在溢出菜单。
- 卡片主体可进入详情，但卡片内按钮点击不得冒泡触发详情。
- 不把滑动手势作为完成核心任务的唯一方式。

### 5.4 表单与弹窗

- 链条、任务组和 RSIP 的新建/编辑在小屏使用全屏表单。
- 表单字段按语义分组，避免一次展示所有高级选项。
- 保存与取消位于稳定、可触达的位置；软键盘出现时不能遮挡当前字段和主要操作。
- 简单选择使用底部抽屉；复杂、危险或包含多步说明的操作使用全屏页。
- 删除、链条清零和 RSIP 违规回滚必须显示影响范围并二次确认。

### 5.5 RSIP

RSIP 是第一阶段一级功能：

- 默认提供适合小屏的列表/树形摘要，不要求用户在小屏画布中精确拖拽。
- 节点卡片整行可点击，常用操作提供足够大的触控区域。
- 创建子规则、编辑节点、执行和违规处理形成可返回的连续流程。
- 违规回滚前列出将受影响的当前节点、子节点和关联关系。
- 现有缩放画布可以保留为高级视图，但不能成为手机端唯一入口。

## 6. 本地数据设计

### 6.1 存储契约

所有业务读写继续经过：

```text
UI → Domain Hook / Service → MomentumStorage → 具体适配器
```

UI 不直接调用 localStorage 或 IndexedDB。IndexedDB 实现必须满足现有 `MomentumStorage` 契约；若契约确实需要扩展，应同步更新本地与 Supabase 实现及相应测试。

### 6.2 分阶段迁移

为了尽快看到移动 UI，同时避免数据迁移和界面改造互相干扰，第一阶段拆成两个可独立验收的增量：

1. 移动 UI 增量：先沿用当前 `localStorageAdapter`，完成响应式布局和核心流程验证，并确保导出可用。
2. 数据可靠性增量：新增 IndexedDB 适配器，完成旧 localStorage 数据迁移后，才把 PWA 视为可长期使用版本。

迁移规则：

- 首次启动 IndexedDB 版本时先只读扫描旧 localStorage 数据。
- 校验成功后在单个迁移事务中写入 IndexedDB。
- 写入后再次读取并核对数量及关键引用。
- 核对成功后记录迁移完成标记，但暂不主动删除旧 localStorage 数据。
- 迁移失败时继续使用旧适配器并提示导出备份，不覆盖原数据。
- 用户确认新版本稳定并完成一次导出后，才提供清理旧数据的可选操作。

### 6.3 可靠性措施

- IndexedDB 使用明确的数据库版本和对象存储版本迁移。
- 关联写入尽量使用同一事务，防止只保存一半。
- 删除、清零和 RSIP 回滚前创建可恢复快照或原子操作日志。
- 应用启动时检查未完成的原子操作并恢复或完成。
- 在浏览器支持时调用持久化存储申请，并向用户显示是否获批。
- 存储空间不足、数据库打开失败或写入失败必须显示错误，不得假报成功。

### 6.4 备份与 APK 迁移

沿用现有导入导出领域逻辑，导出数据至少包含：格式版本、导出时间、链条、会话、历史、RSIP、任务统计和本地设置。导入必须先解析与校验，再让用户选择合并或替换。

PWA 转 APK 时使用：

```text
PWA 导出 JSON → 安装 Tauri APK → APK 导入 JSON → 完整性核对
```

不尝试让 APK 直接读取 Chrome 的站点沙盒。

## 7. 计时与生命周期

- 持久化记录会话状态、开始时间、计划结束时间和暂停累计时间。
- UI 展示可以使用定时器刷新，但业务结果必须根据时间戳计算。
- 页面恢复可见、PWA 重新启动或系统时钟变化时重新计算状态。
- 页面被后台挂起时不假设 JavaScript 定时器持续运行。
- 第一阶段不承诺锁屏期间持续发出精确原生提醒；这属于后续 Tauri Android 通知/前台能力范围。

## 8. PWA 与部署

- 继续使用现有 Vite PWA 配置和 `netlify.toml`。
- 用户 Fork 连接自己的 Netlify 项目，使用固定生产子域名。
- 本地数据与网站来源绑定，因此生产站点名称确定后不要随意更换。
- 每次部署前先导出重要数据；涉及存储迁移的版本必须提供回退说明。
- Service Worker 只缓存应用资源，不替代 IndexedDB 业务存储。
- 新版本更新不能在用户编辑或专注过程中强制刷新；应提示并在安全时机更新。

## 9. 异常处理

- IndexedDB 不可用：回退到已验证的旧本地适配器并提示备份。
- 存储空间不足：停止当前写入，保留内存状态，提示导出和释放空间。
- 导入文件损坏或版本不兼容：拒绝写入，现有数据保持不变。
- 迁移中断：下次启动根据迁移标记和事务状态重新判断，不重复破坏性写入。
- 离线：链条、专注和 RSIP 核心流程继续可用。
- PWA 更新失败：继续运行当前已缓存版本并提供重试入口。
- 危险操作失败：恢复快照或原子日志，并展示明确结果。

错误提示继续使用项目 `toast` 和统一错误类型，不使用 `alert()` 或散落的 `console.*`。

## 10. 测试与验收

### 10.1 自动化测试

- 响应式布局判断：手机 PWA、Tauri Mobile 和桌面窄窗口的行为。
- MobileBottomNav：显示条件、四入口导航、隐藏页面和安全区。
- 任务卡片：开始/预约点击不触发卡片详情，按钮尺寸与可访问名称正确。
- 表单：键盘出现、返回、未保存确认和固定操作区。
- RSIP：列表入口、节点操作、违规影响预览和回滚恢复。
- IndexedDB 适配器：完整 `MomentumStorage` 契约、事务失败和版本升级。
- localStorage 迁移：成功、校验失败、中断重试和不删除旧数据。
- 导出导入：全量往返后对象数量、ID 引用、日期和 RSIP 关系保持一致。
- 计时：后台恢复、重新启动、暂停和系统时间变化。
- 桌面回归：原桌面布局和操作保持不变。

### 10.2 真机验收

- Android Chrome 中可安装到主屏幕并以 standalone 模式启动。
- 360px、390px 和常见大屏手机宽度下无横向溢出，无需双指缩放。
- 高频按钮可以单手稳定点击，底部操作不被浏览器或系统导航栏遮挡。
- 首页、链条、专注与 RSIP 核心路径均可在 1–2 次点击内进入。
- 断网刷新仍可启动，已有本地数据可读取和修改。
- 切换应用或锁屏后返回，计时显示与业务结果正确。
- 导出备份后清除站点数据，可以从 JSON 完整恢复。
- 部署新版本后旧数据仍可访问，迁移失败时可回退。

## 11. 交付顺序

1. 建立移动端真机问题清单和核心路径基线截图。
2. 将布局判断从 Tauri 运行时判断中解耦，让手机 PWA 启用移动外壳。
3. 完成底部四入口、Dashboard 单列重排和任务卡片双按钮触控优化。
4. 完成链条/任务组表单、详情、专注模式和判定流程的小屏适配。
5. 完成 RSIP 列表优先视图、编辑和违规影响预览。
6. 验证现有 JSON 导入导出覆盖第一阶段全部本地数据。
7. 新增 IndexedDB 适配器与 localStorage 安全迁移。
8. 完成离线、更新、后台恢复和真机验收。
9. 部署到用户自己的固定 Netlify 子域名并开始个人试用。
10. PWA 使用稳定后，另行设计 Tauri Android 构建、通知和 APK 数据导入。

## 12. 非目标

- 第一阶段不实现 Supabase 登录或多设备同步。
- 不重写为微信小程序、Flutter、React Native 或原生 Android UI。
- 不重构与移动端可用性无关的业务模块。
- 不承诺浏览器后台持续执行或原生级精确提醒。
- 不在第一阶段深度优化宠物动画和统计图表。
